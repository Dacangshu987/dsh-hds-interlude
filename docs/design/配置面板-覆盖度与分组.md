# 配置面板：覆盖度与分组

> 对象：DSH 设置里的「插件 → hds-interlude」面板（`lib/client.js`）。
> 本文记录**面板覆盖了什么、怎么映射、以及踩过的坑**，避免下次改面板时重复踩。

---

## 一、结构

面板是**手写字段清单**（不是按 schema 自动渲染），因此新增配置项必须显式接进面板，
否则会出现「schema 里有、用户看不到、还不报错」的静默缺失。

| Tab | 内容 |
|---|---|
| **创作** | 故事字段（角色 / 关系 / 世界 / 剧情 四组）+ 关键词；酒馆角色卡导入导出 |
| **节奏** | 时区 / 间隔提示 / 每回合注入时间 / 写故事与发消息节奏 / 各子系统开关（Alter、Agency、Preplan、Urge、时间导演…） |
| **聊天** | IM 通道与多 Bot、表情与图片、消息行为、群聊 @ 门控、**发言意愿与档位**、**打字节奏**、**合并转发预算**、**跨群投递** |
| **扩展** | **世界事件播种器**、**模型特化**、**记忆与维护**（记忆窗口 / 条数守卫 / 休息时段 / 日志级别） |
| **预设/命令** | 机器人命令说明、角色预设管理、状态查看 |

映射是**扁平标量 ↔ 嵌套配置**三处配套：`defaultScalar()`（默认值）、
`scalarFromConfig()`（配置 → 面板）、`buildPayload()`（面板 → 配置）。

## 二、本轮（前端完善）新增覆盖

新增 Tab「扩展」，并把本轮移植进来的能力接进面板：

| 能力 | 面板位置 | 字段 |
|---|---|---|
| 世界事件播种器（rc23） | 扩展 | 启用、检查间隔、挂起/每日上限、最远时限、温度、拉黑名单 |
| 模型特化（rc14） | 扩展 | 档位（auto/off/lite/standard/full）、模型名（自动推断用） |
| 记忆与维护 | 扩展 | 近期记录条目数、额外保留时间窗、长期事实上限、条数守卫、休息时段（每行 `HH:MM-HH:MM`）、窗口内推进间隔、休息时段的主动联系与承诺豁免、日志级别 |
| 打字节奏（rc21） | 聊天（分条旁） | 基础等待、字/秒、最长等待、随机浮动 |
| 合并转发读取（rc6） | 聊天 | 节点上限、字符预算、嵌套深度 |
| 跨群投递（rc11） | 聊天 | 启用、每轮上限、目标白名单 |
| 发言意愿档位（rc23） | 聊天 | 档位（off/五档/auto/custom）+ auto 的 busy/idle/asleep 三态 |

**显示条件**：意愿档位的显示条件从「旧开关 `willingness.enabled`」放宽为
「旧开关 **或** 档位 ≠ off」。否则用户只在 settings.yaml 里设了
`willingnessPreset: auto`（schema 允许）时，配置生效了但面板里找不到它。

## 三、本轮追加：样式统一 / 状态卡片健康指标 / 意愿细调 / 实时日志

### 1. 视觉样式统一

原先有 ~15 处**内联字面量样式**散落各处（同一个视觉意图在不同页面各写一遍），
现在统一命名到 `S` 里，**相同意图只允许一个名字**：

| 新名字 | 取代的原写法 |
|---|---|
| `S.inlineRow` | `{ display:'flex', gap:6 }` |
| `S.inlineRowCenter` | `{ display:'flex', gap:6, alignItems:'center' }` |
| `S.inlineRowWide` | `{ display:'flex', alignItems:'center', gap:8 }` |
| `S.blockGap` / `S.gapTop` | `{ marginTop:6, marginBottom:6 }` / `{ marginTop:6 }` |
| `S.strong` | `{ fontWeight:600 }` |
| `S.textareaSmall` | `Object.assign({}, S.textarea, { minHeight:60/50 })` |
| `S.statGood` / `S.statBad` | 健康指标数字的好/坏两态 |

另核对过：17 个 section 全部带 `className: 'hdsi-section'`（可被样式与测试稳定选中）。

### 2. 运行状态卡片：健康指标

宿主 `/api/hds-interlude/status` 新增 `health`（**聚合所有会话**的内存指标）：
叙事成功率、结构化缺失率、缓存命中率、中位耗时、轮次（含失败数）、主动开口成功数、
统计起点 `sinceAt`；分母为 0 时 `successRate` 照上游口径取 1。

**为什么放进状态卡片**：这几项回答「本次运行以来稳不稳」，而成功率与结构化缺失率是
最常见的事故征兆（模型开始吐不出结构化回复时，缺失率先涨）。没有样本时卡片显式写
「尚无样本」，**不制造虚假的好看数字**。

### 3. 意愿细调参数上界面

原先这批参数只写 `settings.yaml`，用户在面板里既看不到也改不了。现在放进聊天页意愿区的
**「细调参数 ▸」**折叠块（默认收起，避免一屏都是数字）：概率放大系数、意愿半衰期、
每次回复消耗、每条消息累积、被引用时额外累积、命中关键词时额外累积、关键词（每行一个）。

与档位的关系：档位决定**参数来源**，`custom`/`off` 时这些数值才生效；**关键词与档位正交**
（任何档位下都生效）。

### 4. 实时日志（预设/命令页）

宿主新增 `GET /api/hds-interlude/logs?since=<seq>`：返回插件**内存环形缓冲**里最近 200 条
`info`/`warn`（单行截断 400 字，重载即清空）。面板在「预设/命令」页顶部给出日志卡片：
条数、手动刷新、清空本页、**自动刷新 3s（默认关）**、按级别着色的行。

**为什么默认关自动刷新**：打开设置页就一直在发请求没有必要；需要盯现场时自己开。
增量语义（`?since=`）保证轮询时不重复渲染。

## 四、踩过的坑（务必别再犯）

### 1. 同一层写成两个同名键 → 后者**整个覆盖**前者（静默丢配置）

加「维护」段时我在 `buildPayload` 里又写了一个 `runtime: {...}` 与 `proactive: {...}`，
而对象里**已有**这两个键。JS 对象字面量的重复键是后者胜——于是：

- `runtime.autoAdvanceEnabled` / `autoAdvanceIntervalMinutes`（写故事开关与间隔）被丢掉；
- `proactive.enabled`（主动联系开关）被丢掉。

**后果**：用户在面板上点保存，写故事与主动联系会被静默改回 schema 默认值。
`test/client-input.test.mjs` 的「写故事间隔能改」用例当场变红抓到了它。

**规则**：往 payload 里加字段前，先确认目标块**只声明一次**；新增同族字段要
**并进已有块**，不要新起同名键。

### 2. 面板读回值 ≠ 生效值

面板只写它管的那部分字段（其余保持 `undefined` → 不进 payload → 宿主的深合并保留
用户手写的值）。所以新增字段时不要"顺手"给整个块写默认值，否则会把
settings.yaml 里的细调参数抹平。

### 3. 打字节奏的位置

打字节奏是 **IM 投递行为**，放在「聊天」页的分条段落旁（不是「节奏」页）——
「节奏」页管的是写故事/发消息的**时间间隔**。两者容易混。

## 五、测试

`test/client-panel-coverage.test.mjs`（12 项）用小型响应式 hook 跑**真实组件**，
覆盖：

1. 各处新控件**存在**且**读回配置里的非默认值**（面板读错路径就会露馅）；
2. 「渲染 → 改值 → 保存」的**往返**：改动落在正确的嵌套路径上；
3. **未被改动的相关字段仍在**（防止面板漏写把它们抹掉）——第 1 条坑就是这一项最该抓的；
4. 休息时段文本解析：两行 `HH:MM-HH:MM` → 两条 RestWindow。

配套的既有测试：`client.test.mjs`（smoke）、`client-im.test.mjs`（IM 节接线）、
`client-input.test.mjs`（节奏项往返）、`client-styles.test.mjs`（样式纪律）。

## 六、刻意**不**进面板的项

- 意愿细调（概率放大、衰减半衰期、replyCost、关键词…）：留在 `settings.yaml`
  的 `im.group.willingness`，面板不覆盖；
- 模型提供商中心、vision、browser、chatActions、onebot 等上游专属配置：本仓不适用；
- 高级对象的完整编辑（多窗口 restWindows 的逐个编辑）：面板用「每行一条」的
  文本形态表达，够用且不易出错。
