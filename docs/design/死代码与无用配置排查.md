# 死代码与无用配置排查（第一轮）

> 时间：本会话前端完善之后。对象：`dsh-hds-interlude`（`lib/**` 与 `lib/client.js`）。
> 方法：自写静态扫描（无 linter 可用），**结果逐条人工复核**。

---

## 一、怎么查的

三个一次性脚本（不进仓库，跑完即弃）：

1. **未引用导出**：解析每个 `lib/**/*.js` 的 `export function|const|class` 与
   `export {…}`，再统计每个名字在整个 `lib/` + `test/` 里的出现次数
   （同文件内出现次数减 1 = 扣掉定义处）。
2. **前端标量接线**：从 `client.js` 的 `defaultScalar()` 取键名，逐个统计
   `d.KEY =`（配置 → 面板）与 `scalar.KEY`（面板 → 配置/保存）的出现次数，
   找出「只在默认值里」「读了但没从配置读回」「读了但没用」三类。
3. **schema 键引用**：取 `schema.js` 里所有 `key: z.…`，看除 `schema.js` 外全仓是否还有该名字。

**踩到的假阳性陷阱（重要）**：`urge.js` 用**动态拼键**读配置——
`const range = (name, i) => finite(a[name + 'Min'], …)`，于是
`hotMin/hotMax/idleMin/idleMax/burstMin/burstMax/slowMin/slowMax` 在源码里
**从未被字面量写出**，纯字符串搜索会把这 8 个合法配置误判成「无人读」。
**结论**：字符串级扫描必须配人工复核，尤其要搜一遍动态拼键的辅助函数。

## 四、前端配置：**没有**无用项

72 个面板标量全部三处接线完整：

- 「只在默认值里出现」：**0**
- 「面板里有读取、但没从配置读回」：**0**（这类最危险：用户改配置、面板显示旧值）
- 「从配置读回了、但没有任何读取」：**0**

也就是说前端不存在「渲染了但不保存」「保存了但不渲染」「定义了但没用」的字段。

> 已在描述里如实标注，避免用户改完以为生效。
