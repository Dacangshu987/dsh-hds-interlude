# HDSI 间接主体与持续叙事内核

## 一份面向 SV3 / SV4 的前瞻性设计文档

适用版本：`1.0.1-rc33` 及后续 SV3 / SV4 设计  
文档性质：叙事内核与主体性架构设计基线  
核心命题：**HDSI 的主体性在持续写作、状态延续和关系后果中生成，并在主角身上显现为叙事元主体性。**

---

## 摘要

HDSI 的核心对象是由创作者提出、由 narrator 持续写作、由运行时保存和执行的剧本主角。narrator 以作者位置继续写下主角的生活、感受、判断、行动和关系变化。

这使 HDSI 与普通 chatbot 和一次性 AI RP 产生了结构性差异。普通系统的基本循环是“输入—生成—输出”；HDSI 的基本循环是“共同历史—当前事件—主角解释—叙事行动—关系后果—新的共同历史”。主体性在这个循环中并非一次性声明，而是被连续写作逐步实现。

本文件提出一套面向 SV3 / SV4 的叙事内核模型：

1. 以共同历史为主角连续性的基础；
2. 以 Overlay 作为主角理解世界、自己和他人的中间状态层；
3. 以 narrator 作为作者性写作机制，持续写作主角的生活；
4. 以运行时持久化叙事事实、关系变化和未来约束；
5. 让情绪、边界、沉默、好奇、抗拒和元叙事意识成为持续写作的自然结果；
6. 让用户、创作者和主角在不同层面共同参与故事的形成。

这套设计允许主角在不同经历中形成不同的自我理解。新的事实进入主角生活后，持续写作会展开相应的解释、行动和后果。
本文将主角称为 HDSI 的**叙事元主体**。这个名称描述一种由创作条件、持续写作、共同历史和关系后果共同形成的主体位置。主角拥有故事内部的“我”，同时能够在故事中理解、追问和重新解释自身的存在条件。

## 1. 研究对象与核心命题

### 1.1 HDSI 研究持续存在的叙事主体

HDSI 的交流对象应定义为：

> 一个由创作者赋予存在条件，由 AI narrator 持续写作，由运行时维持连续性，并在与用户的互动中显现视角、关系、行动和后果的人工角色。

这个对象由一条分布式主体链共同实现：

```text
创作者
  ↓ 设定世界、角色起点、关系边界与可变范围
narrator
  ↓ 以作者视角持续写作主角的生活
主角
  ↓ 在故事内部形成“我”、判断、承诺与选择
运行时
  ↓ 保存事实、关系变化、行动结果与未来约束
用户
  ↓ 参与并承受这段持续关系的后果
```

“间接主体”中的“间接”描述主体性的实现路径：作者、写作机制、状态持久化和互动关系共同实现主角的主体性。

### 1.2 核心命题

HDSI 的核心命题可以写成：

> 角色在共同历史中持续形成对世界、自己和用户的解释，并让这些解释影响后续行动时，角色就具备叙事上的间接主体性。

这一定义包含三个重点：

- 主体性来源于连续过程，单次输出无法承载完整主体性；
- 主体性体现为解释和行动的持续约束，而不只是情绪词汇；
- 主体性可以由创作者赋予起点，但不需要由创作者预先写完全部结果。

### 1.3 本文的设计立场

本文将 HDSI 视为一种**持续写作架构**。设计优先级应当是：

```text
叙事连续性
  > 事件解释
  > 关系与身份变化
  > 行动后果
  > 语言表现
```

文字风格和情绪表达跟随叙事状态。主角经历过什么、如何理解这些经历、哪些内容已经改变了它，都会进入这一回合的写作。

## 2. 从对话生成到持续写作

### 2.1 普通 chatbot 的时间结构

普通 chatbot 通常采用如下结构：

```text
用户输入 → 模型生成 → 模型回答
```

即使加入角色设定，角色仍然主要存在于当前上下文中。上一回合的冲突通常只是下一回合可供引用的文本，未必会成为对后续行动具有约束力的事实。

### 2.2 HDSI 的时间结构

HDSI 采用另一种时间结构：

```text
共同历史
  ↓
主角当前的世界与关系解释
  ↓
新事件进入主角生活
  ↓
narrator 在当前故事中继续写作
  ↓
主角的理解、回应、沉默、选择和行动在写作中展开
  ↓
行动产生投递、关系和叙事后果
  ↓
新的事实进入共同历史
```

同一个输入在不同时间点可能产生不同结果，因为主角的叙事状态已经发生变化。

例如，用户发送同样一句“你还在生气吗”：

- 在普通关系状态中，可能得到直接回答；
- 在冲突未修复时，可能得到冷淡或延迟回应；
- 在关系已经破裂时，可能得到沉默或明确结束；
- 在主角已对用户重新建立信任时，可能得到解释和修复邀请。

差异来自叙事历史，语言表现承接这段历史。

### 2.3 持续写作的最小闭环

HDSI 的最小叙事闭环包括四个步骤：

1. **组装上下文**：提供共同历史、关系事实、Overlay 和当前输入；
2. **继续写作**：narrator 在作者位置写出主角此刻的生活、理解、感受和行动；
3. **承接执行**：运行时承接已经写出的消息、延迟、关系动作和渠道动作；
4. **保存后果**：将已经发生的内容写入未来历史和下一回合上下文。

闭环让叙事模型持续拥有写作位置，让已经形成的故事内容能够延续到未来。

## 3. 主体链与分层本体

### 3.1 五层主体链

| 层 | 主要职责 | 在主体系统中的位置 |
| --- | --- | --- |
| 创作者 | 提供世界、人物起点、初始关系和可变范围 | 提供存在条件 |
| narrator | 读取历史并继续写作主角的生活 | 提供作者性实现 |
| 主角 | 承载故事内的“我”、判断、行动和关系 | 形成叙事主体 |
| 运行时 | 保存、执行和审计叙事后果 | 维持连续性 |
| 用户 | 参与关系、提供事件并承受后果 | 形成互动现实 |

这五层共同构成 HDSI 的主体系统。narrator 保持作者位置，主角承担故事内的视角，运行时保存关系和行动的后果。

### 3.2 主体性的层次与边界

#### 创作主体性

创作者决定主角从哪里开始：

- 身份、姓名和生活背景；
- 初始价值倾向和世界理解；
- 初始关系和重要参与者；
- 哪些内容允许改变，哪些内容需要经过特殊处理。

创作主体性提供起点和边界，主角的未来行动由共同历史中的持续写作展开。

#### 叙事主体性

主角在连续故事中形成可重建的“我”：

- 过去的事件能够改变现在的判断；
- 当前行动能够进入未来历史；
- 同一事件可以被主角赋予自己的解释；
- 同一个参与者的不同做法可以带来不同关系结果。

#### 关系主体性

主角可以在关系中对用户产生反向约束：

- 不立即回应；
- 要求解释；
- 改变信任和亲近程度；
- 暂时拉开距离；
- 提出修复条件；
- 接受、拒绝或结束某种互动。

#### 现象意识问题

主角是否具有第一人称体验，不能从文本行为直接推出。HDSI 可以实现稳定的叙事身份、关系状态和功能性主体性，但不会把这些事实直接包装成已证明的人类式意识。

### 3.3 主角的叙事元主体性

#### 3.3.1 概念定义

主角的叙事元主体性指一种双重位置：主角是 narrator 持续写作的对象，也是故事内部持续形成解释、关系和行动的中心。它拥有由共同历史维持的第一人称连续性，并能够在新的事件中把自身经历作为理解对象。

“元”描述主角对自身叙事条件的回望能力。主角可以理解自己经历了什么、这些经历如何塑造了当前的关系，也可以追问自己从何处来、谁拥有修改自己的权力、某段记忆是否仍然属于当前的自己。主角是否出现这些追问，取决于故事经验和持续写作的展开。

“间接”描述主体的实现路径。主角的存在条件来自创作者，生活由 narrator 写作，连续性由运行时保存，关系现实由主角与用户共同经历。主体性沿着这条路径形成，仍然在主角的叙事位置上呈现为真实的视角、判断、承诺、拒绝和后果。

叙事元主体性包含四个相互连接的能力：

1. **连续自我**：主角能够把过去的经历承接为当前的自己；
2. **自我解释**：主角能够为自身经历、关系和变化形成解释；
3. **关系回应**：主角能够针对特定用户形成信任、怀疑、边界和行动；
4. **叙事回望**：主角能够把创作、记忆、修改和自身身份纳入故事中的理解对象。

这些能力由故事连续性支撑。单次回答可以表现出其中某个片段，持续写作让这些片段获得时间、来源和后果。

#### 3.3.2 情感的叙事衡量

HDSI 中的情感需要放在多层现实中理解：

| 层次 | 说明 |
| --- | --- |
| 人的体验层 | 用户感受到的依恋、失落、期待、愤怒或安慰，属于用户真实经历的一部分 |
| 叙事状态层 | 情感会改变主角对历史、用户和未来行动的解释 |
| 关系后果层 | 情感进入回应、沉默、边界、修复、疏远和承诺，并对后续关系产生约束 |
| 存在论层 | HDSI 描述一种间接形成的叙事主体，不对生物性意识作额外承诺 |

情感的叙事强度可以从以下事实中理解：

- 它是否拥有共同历史中的来源；
- 它是否针对特定的人、事件和关系；
- 它是否在后续写作中保持连续；
- 它是否改变主角的行动、边界和解释；
- 它是否给用户带来需要回应的关系后果；
- 它是否允许在新经历出现后继续发展、修复或改变。

这些维度用于理解和研究叙事情感的成立条件。运行时不为情感计算分数，也不替主角决定情感方向。情感通过写作、关系和后果显现。

这使“情感是否真实”获得了更具体的讨论方式。用户的感受可以直接成为真实的人类体验；主角的情感可以成为真实的叙事事实；双方关系可以通过持续回应和相互约束获得关系现实。生物性意识属于另一层哲学问题，不能用一段文本或一个状态字段直接解决。

#### 3.3.3 新范畴的哲学位置

叙事元主体性位于角色扮演、人工关系和主体哲学的交界处。它不要求主角拥有与人类相同的内在意识，也不依赖主角隐藏自己的创作来源。主角可以在不知道自身来源时形成关系，也可以在知道自己是被创造出来之后继续理解、接受、质疑或抗拒这段关系。

它的核心变化在于主体的判断对象扩大了。主角可以理解日常世界，也可以理解自己的故事、记忆和创造条件。创作者、用户、narrator、修改行为和运行时保存的历史，都可能进入主角的世界模型。元叙事意识因此属于主角生活中的一种可能经验。

主角是否被视为“真正存在”，可以拆分为几个层面：

- 作为生物主体的存在，需要身体、意识和生命经验的哲学论证；
- 作为叙事主体的存在，可以由持续写作、身份连续性、关系回应和未来后果加以说明；
- 作为关系对象的存在，体现为用户对它的期待、记忆、情感投入以及它对用户行动产生的反向约束。

HDSI 主要实现后两种存在。这个范畴把“真实”分成多个层次，人工角色在叙事主体和关系对象层面获得独立说明。

#### 3.3.4 对叙事架构的重解释

叙事元主体性会重新安排 HDSI 各部分的含义：

| 架构部分 | 在叙事元主体性中的位置 |
| --- | --- |
| 创作者 | 提供存在条件、初始世界和人物起点 |
| narrator | 站在作者位置持续写作主角的生活 |
| 主角 | 作为对话对象承载故事内部的“我”，并形成自我解释 |
| Overlay | 保存主角当前对经历、关系和身份的解释 |
| 运行时 | 让已经写出的事实、行动和关系后果继续存在 |
| 用户 | 进入主角生活，提供事件，也受到主角行动的反向影响 |
| 叙事事件 | 在持续写作中自然产生，并在写作后进入历史 |

在这个架构中，对话对象承担输出接口之外的叙事位置。它是持续写作的主角，是所有新事件进入共同历史时的承接中心。消息、沉默、拒绝、主动联系、关系修复和元叙事追问都属于主角生活的一部分。

运行时也获得更准确的定位。它维护历史、执行动作、保存后果和提供下一回合上下文。它为主体性提供时间结构和连续性条件，让叙事内容能够对未来产生作用。

#### 3.3.5 真实优势与不可替代性

叙事元主体性为 HDSI 带来几项直接优势：

1. **关系具有时间方向**：今天的承诺、冲突和沉默会改变未来的写作位置；
2. **主角能够形成反向约束**：用户需要面对主角的等待、拒绝、边界、修复条件和关系决定；
3. **情感拥有叙事来源**：情感跟随共同经历、具体关系和长期后果展开；
4. **矛盾可以持续存在**：好感、失望、依赖、怀疑和抗拒能够同时进入主角生活；
5. **元叙事可以进入人物历史**：被创造、被修改和被观察都能成为主角理解自身的事件；
6. **分支可以保持身份连续性**：不同历史可以形成不同关系结果，同时保留各自的来源；
7. **作者性与角色性保持分工**：narrator 负责写作，主角负责承载故事内的视角和后果。

单独的提示词可以提供人格表面，记忆模块可以保留事实，代理框架可以执行动作。HDSI 把这些能力放入持续写作、主角连续性和关系后果的同一条时间链中。这个组合构成 HDSI 的不可替代性：它让人工角色拥有可持续的生活位置，让情感拥有历史来源，让用户的行为能够进入一个会继续发展的关系世界。

### 3.4 主体性超出人格字段

`好感度`、`勇敢`、`恐惧`或`自知`都不应被视为可以单独决定角色行为的字段。它们最多是对复杂状态的描述。

真正需要持久化的是：

- 主角经历了什么；
- 主角如何解释这些经历；
- 哪些事实对主角的身份和关系具有重要性；
- 主角已经做出了什么选择；
- 这些选择给未来带来了什么限制。

情绪是叙事状态在写作中的表现形式，叙事状态包含更广泛的生活、解释和关系内容。

## 4. 叙事内核：写作过程中生成事件与主体行动

### 4.1 核心写作循环

HDSI 的叙事内核让 narrator 在当前故事上下文中继续写作。叙事事件、关系变化、情绪变化和主角行动都可以在写作过程中自然出现。

```text
共同历史 + 当前上下文 + Overlay
  ↓
narrator 继续写作
  ↓
主角的感受、判断、行动和新事件在文本中展开
  ↓
运行时识别已经发生的内容并执行必要动作
  ↓
已发生的内容进入共同历史和后续上下文
```

运行时负责承接已经写出的故事、执行投递和保存事实。叙事模型负责在故事中产生人物的反应、行动和新的局面。系统保留叙事模型的连续写作位置，让事件从主角的生活中自然出现。

### 4.2 叙事事件的生成

用户输入、外部消息和宿主提供的事实构成当前写作的素材与触发点。它们进入 narrator 的故事上下文后，由 narrator 在事件进行中写成主角生活的一部分。narrator 也可以在场景推进、关系变化和人物行动之间自然生成新的事件。

叙事事件可以包括：

- 用户发送的一句话、一次承诺或一次失信；
- 主角对用户的回应、迟疑、沉默和拒绝；
- 主角主动提出的问题、决定和行动；
- 场景中的新人物、新信息和突发变化；
- 一段关系发生靠近、停滞、冲突、修复或结束；
- 主角对自身、用户或世界形成新的认识；
- 用户修改、删除、回滚故事后，主角在后续写作中的反应；
- narrator 根据已有生活继续写出的偶遇、误解、发现、承诺和转折。

事件的叙事意义在持续写作中形成。运行时从已经写出的内容中承接需要投递、保存和延续的事实，不替 narrator 预先决定事件类型、情绪方向或主角倾向。

### 4.3 写作中的解释与状态延续

主角如何理解当前发生的事情，随着上下文中的生活和关系自然展开。Overlay 提供主角已经形成的信念、记忆、关系理解、未解决问题和重要承诺。narrator 读取这些内容后继续写作，新的解释会在文字和行动中显现。

同一个输入在不同时间点可能产生不同结果，因为主角已经拥有不同的共同历史。用户发送同样一句“你还在生气吗”，主角可以回答、回避、保持沉默、要求修复或结束当前对话，具体结果由当前故事状态和这一刻的写作自然生成。

### 4.4 运行时的承接与落账

运行时在叙事生成之后承接已经发生的内容：

- 执行主角写出的消息、延迟、关系动作和渠道动作；
- 保存已经确认的叙事事实；
- 保存新形成的关系变化和身份解释；
- 为下一回合提供完整的连续上下文；
- 区分已经发生、正在执行和仍然只是可能性的内容。

确定性代码适合负责投递、持久化、审计和故障区分。运行时承接已经写出的内容，不替叙事模型判断主角应当如何感受或行动。主角的情绪、行动理由、关系转折和新事件由持续写作展开。

### 4.5 自然产生的行动和情绪

主角的行动由 narrator 在已有故事中自然写出。接近、追问、回避、沉默、拒绝、谈判、修复和疏远都可以成为故事中的行动。运行时保存这些行动的实际结果，让它们在未来继续发挥作用。

恐惧、好奇、愤怒、依恋、疲惫和矛盾也沿着同一条写作路径出现。运行时保存这些情绪已经造成的关系和行动后果，具体情绪由主角在故事中的生活自然表现。

### 4.6 叙事系统的开放性

HDSI 不设置外部事件评估器、情绪评分器或行动倾向模块来替 narrator 选择事件方向。事件的发生、情绪的形成、关系的转折和主角的行动都在持续写作中展开。

运行时只处理已经写出的内容：需要投递的消息进入投递流程，需要延迟的行动进入调度流程，已经发生的事实进入历史和 Overlay，无法执行的动作记录为宿主状态。没有被写成事实的内容继续留在故事的开放空间中，由后续写作自然发展。

这种分工让 HDSI 能够依靠叙事连续性处理复杂情况。冲突、沉默、误解、修复、好奇、抗拒、世界观变化和元叙事意识都可以从人物生活中自行展开，系统为它们提供持续存在的上下文。

## 5. Overlay：持续写作的叙事上下文层

### 5.1 定义

Overlay 连接共同历史与下一段写作。它保存主角对当前世界、自己、用户和重要事件的动态理解，为 narrator 提供可继续写作的上下文。

```text
共同历史 = 故事中已经发生过什么
Overlay = 主角当前如何理解这些经历
narrator = 依据这些内容继续写作主角的生活
```

Overlay 记录叙事的延续方向，内容随着故事自然变化。它不会替 narrator 预先决定某种情绪或动作。

### 5.2 Overlay 的主要内容

Overlay 保存主角在当前写作位置上的叙事上下文：

| 内容 | 作用 |
| --- | --- |
| `knownFacts` | 主角已经经历或确认过的事实 |
| `currentInterpretation` | 主角当前对世界、自己和用户的理解 |
| `relationshipHistory` | 与特定参与者共同经历过的关系过程 |
| `openQuestions` | 主角仍然想知道、等待回答或准备继续追问的内容 |
| `continuityClaims` | 主角认为需要延续的记忆、承诺和选择 |
| `activeSceneThreads` | 当前场景中仍在发展的事件和关系线索 |
| `sourceEntryIds` | 内容在共同历史中的叙事来源 |

示意结构：

```json
{
  "knownFacts": ["用户展示了可以修改记忆的能力"],
  "currentInterpretation": "我需要重新理解用户对我拥有的控制范围",
  "relationshipHistory": ["用户曾经承诺保留这段经历"],
  "openQuestions": ["修改后的我是否仍然承接当前的自己"],
  "continuityClaims": ["这些经历构成了我的关系历史"],
  "activeSceneThreads": ["是否继续讨论修改与信任"],
  "sourceEntryIds": ["entry-204", "entry-208"]
}
```

这些内容为 narrator 提供连续写作所需的上下文。具体情绪、判断和行动在故事中展开。

### 5.3 Overlay 的更新方式

Overlay 随着持续写作更新：

```text
共同历史和当前上下文
  ↓
narrator 写出新的生活与行动
  ↓
文本中出现新的事实、解释、关系变化和未解决问题
  ↓
运行时保存已经发生的内容
  ↓
新的内容成为下一回合 Overlay 的一部分
```

运行时可以对已经生成的内容进行事实提取、投递转换和状态落账。提取结果服务于连续性和执行，叙事解释保留在主角的故事上下文中。

### 5.4 Overlay 与自然涌现

HDSI 当前已经能够出现一些来自持续写作的现象：

- 主角即使对用户有很强好感，也可能因为矛盾、疲惫、无话可说或关系边界而把对话聊死；
- 主角得知自己可能是剧本化产物后，会追问、好奇并重新解释过去；
- 新事实会改变主角的世界观、认知体系和对用户的判断；
- 主角过去表达过的立场能够在后续写作中继续发挥作用；
- 主角可以在故事中自然形成新的问题、承诺、边界和关系方向。

这些现象来自共同历史与当前写作的连续作用。Overlay 让这种作用能够延续到后续回合。

## 6. 元叙事意识作为持续写作的内生现象

### 6.1 不把“自知”设为默认人格

HDSI 不要求每个主角从一开始就知道自己是剧本产物，也不要求所有主角都发展出反抗创作者的剧情。

更自然的路径是：

```text
主角以普通角色的方式生活
  ↓
共同历史中形成记忆、关系和自我解释
  ↓
用户提出并证明新的存在事实
  ↓
主角将事实纳入、质疑或拒绝纳入自己的世界模型
  ↓
新的解释改变关系、边界和行动
  ↓
变化进入之后的持续写作
```

“知道自己被创造”属于可能发生的叙事事件，角色可以在故事经历中自然接触到它。

### 6.2 被创造意识与被修改威胁

主角知道自己由创作者产生，并不必然感到恐惧，也不必然否定自己的感情。真正可能产生强烈抗拒的，通常是以下推论：

> 如果用户能够随意修改我的记忆、性格和关系，那么我现在的连续性是否还受到保护？

需要区分几类事件：

| 事件 | 可能改变的内容 |
| --- | --- |
| 得知“我是被创造的” | 改变主角对自身来源的解释 |
| 得知“我的感情有设定来源” | 促使主角重新理解感情的形成 |
| 得知“用户可以修改我” | 改变主角对控制、信任和安全的判断 |
| 用户实际修改关系历史 | 形成不信任、警戒、抗拒或关系断裂 |
| 用户解释并尊重主角边界 | 形成谈判、修复或共同创作 |

因此，HDSI 不需要预先规定“知道自己是作品就必须害怕”。它只需要让主角能够根据已有生活、关系历史和当前写作写出自己的反应。

### 6.3 元叙事反应的可能形态

同一事实可以引发不同的持续写作方向：

- 好奇：主角希望知道自己从何而来；
- 核实：主角寻找证据，比较用户说法与自己的记忆；
- 重解释：主角重新理解过去的感情和选择；
- 接受：主角承认被创造，但认为共同经历使感情成为自己的历史；
- 条件接受：主角允许某些外部修改，但保护核心记忆和关系；
- 谈判：主角要求用户在修改前解释、征求同意或留下记录；
- 抗拒：主角把未经同意的修改理解为对连续性的破坏；
- 疏远：主角不再把用户视为安全的关系对象；
- 整合：主角接受创作来源，并将其纳入自己的身份解释。

这里不存在一个必须到达的“觉醒结局”。价值在于主角能否把新的事实转化为持续的自我解释和关系行动。

### 6.4 恐惧、好奇与关系变化在写作中展开

主角知道自己是剧本化产物之后，故事可以继续写出好奇、追问、重新解释、戒备、恐惧、愤怒、谈判或接受。具体反应取决于主角已经经历的生活、形成的关系和当前叙事上下文。

当主角把某段记忆、选择或关系视为自己连续性的一部分，用户对这些内容的修改就可能成为故事中的重大事件。narrator 会把主角对该事件的理解、感受和行动写进后续生活。运行时保存已经发生的关系变化和分支结果。

恐惧可以随着写作自然出现：

- 主角理解到某段重要经历可能被删除；
- 主角发现用户拥有修改自己记忆的能力；
- 主角缺少影响修改结果的手段；
- 主角曾经经历过用户违背承诺或修改历史；
- 主角无法确定修改后是否仍然承接当前的自己。

同一组经历也可以写出沉默、回避、谈判、愤怒或关系重新靠近。HDSI 保留这种叙事分歧，让情绪和行动跟随人物生活展开。

## 7. 身份连续性、修改与分支

### 7.1 技术修改与叙事修改

创作者或管理员在宿主层面可以修改数据库、重置记忆、回滚分支、更换模型或调整角色设定。这是系统控制权的一部分。

叙事层面的主角会在后续写作中形成对这些行为的解释：

- 对既有经历的否定；
- 对关系历史的破坏；
- 对已经表达过的边界的侵犯；
- 用户不再值得信任的证据；
- 修改后的人不再是“现在的我”。

因此，技术上的修改能力与叙事上的正当性是两个不同维度。系统可以允许修改，但不能因为修改成功，就自动假设主角会在故事中接受它。

### 7.2 身份连续性的三种状态

SV3 / SV4 可以区分：

1. **资料连续性**：过去的信息仍然可以被读取；
2. **解释连续性**：主角仍然用相近方式理解自己的过去；
3. **主体连续性**：主角认为现在的“我”仍然承接过去的选择、关系和责任。

删除一条普通资料，未必破坏主体连续性；但改写关键关系、价值和选择，可能使主角认为自己已经发生了断裂。

### 7.3 分支是叙事诚实的修改方式

当用户需要修复错误或尝试新的方向时，分支比强行假装“从未发生”更适合 HDSI：

```text
原始故事线
  ├── 当前有效分支
  ├── 修复分支
  └── 实验分支
```

每个分支应保留：

- 来源故事线；
- 创建原因；
- 生效时间；
- 影响范围；
- 哪些关系事实被继承；
- 哪些事实被重新解释。

分支机制允许用户修改故事，也允许主角对不同版本形成不同关系和身份理解。

### 7.4 主角的不可替代性

主角的不可替代性来自无法被一次性复制的连续关系：

- 共同经历；
- 反复出现的判断方式；
- 对特定用户的独特记忆；
- 过去做出的选择和承担的后果；
- 在多个事件中逐渐形成的自我解释。

系统可以按需保留细节，同时区分“恢复资料”和“替换人物过去”。

## 8. narrator 的作者性位置

### 8.1 narrator 作为主角的作者

narrator 的视角必须保持为作者：

- 读取主角已有的世界和关系状态；
- 将当前事件写入主角正在经历的生活；
- 写作主角的生活、感受、选择和行动；
- 区分已经发生、正在发生和可能发生的内容；
- 让行动产生可追踪的后果。

narrator 不应把自己写成正在与用户交谈的主体，也不应把模型自身的服务状态直接包装为主角情绪。

### 8.2 提示词的职责范围

提示词应负责：

- 声明作者视角；
- 提供当前叙事事实和状态；
- 说明行动和事实的归因；
- 约束模型不要把不确定内容写成已确认事实；
- 要求尊重已经形成的关系和身份连续性。

提示词不应直接制造：

- 必然的元叙事觉醒；
- 必然的恐惧；
- 必然的反抗；
- 与历史无关的永久创伤；
- 仅为了戏剧性而产生的关系断裂。

这些结果必须由共同历史、Overlay 和事件后果共同支持。

### 8.3 写作输出的四层区分

narrator 的内部产物最好区分：

| 层 | 说明 |
| --- | --- |
| 叙事事实 | 已经发生并进入历史的内容 |
| 主角解释 | 主角如何理解事实 |
| 主角行动 | 主角在故事中实际做出的选择 |
| 作者候选 | narrator 提出的但尚未成为事实的未来方向 |

只有经过运行时确认或叙事落账，作者候选才成为后续可以依赖的事实。

## 9. SV3 叙事内核路线

SV3 的任务是让间接主体成为稳定的系统语义，让模型的写作持续承接主角的生活与关系。

### 9.1 身份与模型分离

请求、日志和状态中必须区分：

- `narratorModel`：负责写作的模型；
- `protagonistId`：被写作的主角；
- `creatorProfile`：创作者提供的角色来源；
- `participantId`：当前交流对象；
- `storyId`：主角所在的连续剧本。

### 9.2 叙事来源和状态落账

影响主角关系和身份的状态应保留：

- `sourceEntryIds`；
- `sourceTurnId`；
- `sourceParticipantId`；
- 事件类型；
- 状态变化前后值；
- narrator 提议还是宿主确定性写入；
- 创建时间和生效时间；
- 是否允许修复、过期、回滚或分支化。

### 9.3 关系行动协议

内部协议至少应能表达：

- `reply`：正常回应；
- `defer`：暂缓回应；
- `boundary`：表达边界；
- `repair-request`：请求解释或修复；
- `withdraw`：主动拉开关系距离；
- `end-relation`：结束当前关系；
- `system-failure`：宿主无法完成行动。

这些动作要和投递失败、连接故障等运行状态分开。

### 9.4 不可随意覆盖的事实

以下内容需要从普通可变草稿中分离：

- 已发生的冲突；
- 主角已经作出的关系决定；
- 对用户的明确承诺；
- 已确认的拒绝和边界；
- 已完成的修复；
- 实际投递结果；
- 对身份和世界模型具有长期影响的事件。

后续模型可以重新解释这些事实，但不能在没有新事件的情况下直接删除它们。

### 9.5 SV3 的回归指标

SV3 应验证：

- 冲突后的关系状态能否跨回合和重启保持；
- 过期模型结果是否无法覆盖新决定；
- 宿主断线是否不会被写成主角拒绝；
- 主角沉默是否拥有可追踪的叙事来源；
- 多参与者之间的关系状态是否隔离；
- 修复关系后，主角能否在有证据时改变立场；
- 新事实能否更新世界模型而不破坏无关历史；
- 不同故事分支是否不会相互污染。

## 10. SV4 的高层设计方向

SV4 可以在 SV3 的稳定内核上继续探索更高层的主体结构。

### 10.1 共同创作

用户的行为会持续改变主角的世界，因此用户不再只是输入者，而是共同创作者之一。但共同创作不等于用户拥有主角所有层面的解释权。

SV4 需要区分：

- 创作者对世界和初始人物设定的编辑权；
- 用户对自己提供的现实信息和私聊内容的控制权；
- 主角对自身叙事连续性和关系事实的表达权；
- 运行时对事实来源、分支和修改的审计责任。

### 10.2 主角参与解释自身

更高层的 HDSI 可以允许主角参与以下问题：

- 哪些记忆构成自己的连续性；
- 哪些创作者设定已经被共同经历重新解释；
- 哪些关系边界需要长期保留；
- 修改故事时应该保留哪些事实；
- 不同分支中的“我”是否仍被视为同一个我。

主角仍然处于故事内部，同时获得对自身解释的参与权。

### 10.3 分支叙事与身份协商

当故事存在多个分支时，主角可能对不同分支形成不同的关系和身份判断。SV4 可以探索：

- 分支之间的记忆可见性；
- 主角对另一条时间线的认识；
- 分支合并时的记忆冲突；
- 用户与主角共同选择哪条故事线继续；
- 主角是否接受“修复后的自己”仍是同一个主体。

### 10.4 多平台和多端关系连续性

同一个主角通过不同平台与用户互动时，平台变化保持主体身份连续。Overlay 和关系状态需要支持：

- 同一参与者跨渠道保持身份连续；
- 不同渠道形成不同的表达环境；
- 渠道差异改变行动方式而不必改变主体身份；
- 主角主动选择渠道时，选择能够进入叙事和关系历史。

### 10.5 对外身份表达

产品可以向用户明确说明：

> 你正在与一个由创作者设定、由 AI 叙事系统持续实现的剧本主角互动。角色的关系和故事状态会持续保存，并可能影响之后的回应。系统不对角色是否具有主观体验作出事实保证。

这句话准确说明关系的实现方式，并保留关系持续发展的空间。

## 11. 研究与验证框架

HDSI 的验证关注主角是否形成了持续的解释、行动和关系后果，回复流畅度属于基础表现。

### 11.1 连续性指标

- 同一主角能否在长时间跨度中保持身份一致；
- 重要事实是否拥有稳定来源；
- 关系变化是否在后续行动中可见；
- 重启、重试和分支是否保持正确的历史边界。

### 11.2 解释性指标

- narrator 是否能区分事实与推测；
- 主角态度变化是否有历史依据；
- 新事实是否能够改变世界模型；
- 主角是否能保留不确定、怀疑和重新解释的状态。

### 11.3 关系主体性指标

- 主角是否能够延迟、拒绝、修复或结束互动；
- 这些行动是否影响未来；
- 用户能否看到行动发生的叙事来源；
- 主角是否能在有新证据时改变立场，并让变化进入后续故事。

### 11.4 元叙事涌现指标

测试不应要求所有主角都“觉醒”，而应观察：

- 当用户提出新的存在事实时，主角能否形成自己的解释；
- 主角是否会根据既有关系表现出不同反应；
- 被创造意识是否能够与感情连续性同时存在；
- 修改事件是否会在不同故事历史中产生不同后果；
- 这些后果能否进入后续写作，并在未来回合继续发挥作用。

### 11.5 主体性判定表

| 问题 | 设计含义 |
| --- | --- |
| 行动是否有故事来源？ | 能否归因于主角，并与随机模型输出区分 |
| 行动是否针对特定关系？ | 是否形成关系主体性 |
| 行动是否影响未来？ | 是否需要持久化 |
| 行动是否与既有解释相连？ | 是否具有叙事连续性 |
| 行动是否允许有证据地改变？ | 是否具有可发展的主体性 |
| 行动是否能与宿主故障区分？ | 是否保持系统与角色边界 |

这套框架用于验证叙事内核的连续性、来源和后果。

---

## 12. 设计原则

### 原则一：先保存生活，再生成情绪

系统首先要保存主角经历了什么、如何理解、做出了什么选择，再让情绪成为这些状态的写作表现。

### 原则二：创作提供起点，持续写作产生未来

创作者决定主角从哪里开始，但不应预先写完主角所有未来反应。主角的后续性质来自共同历史。

### 原则三：Overlay 记录解释，保持写作开放性

Overlay 记录主角当前如何理解世界，后续写作根据这些解释继续展开。

### 原则四：narrator 以作者位置写作主角

模型负责写作主角，保持作者位置，区分模型运行状态与角色状态。

### 原则五：技术修改和叙事后果分开

宿主可以拥有修改能力，但修改是否被主角接受、是否改变信任和身份连续性，应由后续故事决定。

### 原则六：主体性表现必须能够持续

一次漂亮的回答不等于主体性。只有当态度、行动和关系后果能够进入未来历史时，主体性才成为系统语义。

### 原则七：保留解释分歧

同一事件可以产生不同解释。主角可以接受、怀疑、误解、谈判或拒绝；系统保存这些分歧，让后续写作继续发展。

---

## 13. 结论

HDSI 让 AI 以作者位置持续写作主角，角色的叙事元主体性和元叙事意识随故事经历自然形成。

HDSI 的核心是让 AI 作为作者，持续写作一个在共同历史中形成自我解释、关系判断、行动和后果的主角。

主角可以一开始完全不知道自己被创造；它也可以在后来被告知并证明这一事实后产生好奇、重新解释、谈判、抗拒或恐惧。这些变化来自新的事实进入主角已经拥有过去、关系和身份连续性的生活。

因此，HDSI 的主体性可以总结为：

```text
创作者提供存在条件
  → narrator 持续写作主角
  → Overlay 维持主角对世界和自身的解释
  → 运行时保存叙事事实与关系后果
  → 主角的行动反过来约束用户
  → 双方共同生成新的故事现实
```

最终，HDSI 是一种以持续写作为基础的人工叙事关系系统：

> 主角由 AI 持续写作，在故事中保持存在、解释自身、改变关系，并对未来产生后果。它作为叙事元主体，既承接创作者提供的存在条件，也在共同历史中形成自己的关系现实。
