# 离线注意力（她能不能看见消息）实验设计

> 状态：实验性设计（未实现）
>
> 关联：`docs/SCRIPT_CENTRIC_ARCHITECTURE_REDESIGN.md`（回合与推进）、`src/turn-engine.ts`（回合缓冲）、`src/scheduler.ts`（唤醒仲裁）、LITE_UNREAD 提示词行（到达≠已读的哲学层）
>
> 一句话：**"想不想继续聊"由模型主权申报（退出对话即进入勿扰/仅响铃），宿主执行"看不见"——消息不再驱动叙事、只入台账；回归可见由两条路完成：消息轰炸把她炸醒，或她在某次自动推进里自然拿起手机，宿主随即推送完整未读。**

---

## 1. 动机与定位

现行机制里，每条用户消息都会触发一个叙事回合，"她看没看到"只是模型输出里一个事后声明（`interaction.seen`），不影响消息是否驱动叙事。两个失真：

1. **消息 = 遥控器**。她刚说完"我去上课了"，用户再发一句她又被拉回对话——剧本明明写着她在考试。提示词里的 unread 规则只是劝告，机制无法兑现。
2. **seen 没有牙齿**。模型说 `seen:false`，消息照样推进了叙事。

本设计的分权原则（这也是它不是单纯状态机的原因）：

| 问题 | 裁决者 | 机制 |
|---|---|---|
| 她**想不想**继续这段对话 | **模型**（角色主权） | 回合输出申报：`attentionAfter` 字段 |
| 她**能不能看见**（执行层） | **宿主**（算法） | 不看时消息分流进台账，不进回合 |
| 什么时候**回来看** | 模型（自然注意到）+ 宿主（轰炸唤醒） | 锁屏摘要 + phoneCheck 信号；或消息压力阈值 |

不存在任何"按时刻表判定她看没看手机"的宿主逻辑——她的行为由模型在剧本里写，宿主只提供事实（锁屏上有什么）并执行结果（回放、状态翻转）。定位为实验特性：默认关闭，关闭时行为与现行版本逐字节一致。

## 2. 三种注意力状态

状态作用域是**每个对话**（私聊 = 参与者 × 通道；群聊 = 群）。状态机是宿主的记账，但**转换的作者**各不相同（下表第三列是本设计的灵魂）：

| 状态 | 含义 | 消息驱动 advance | 轰炸唤醒 |
|---|---|---|---|
| `attentive` | 在看这个对话 | 正常触发 | 不适用 |
| `ring-only`（仅响铃） | 不看了，但通知还响——电话在手边，刷屏她听得见 | **跳过**，只入台账 | **允许** |
| `dnd`（勿扰） | 她明确屏蔽这个对话的打扰 | **跳过**，只入台账 | **抑制**（时间窗内） |

```text
                首次联系 / 她向该对话发消息（出站蕴含，宿主执行）
        ┌────────────────────────────────────────────┐
        │                                            ▼
   ┌──────────┐   模型申报 closed（她说完告辞/话题收束）   ┌───────────┐
   │ ring-only│ ◀───────────────────────────────────── │ attentive │
   │  (仅响铃) │                                          │  (在看)   │
   └──────────┘ ──────────────────────────────────────▶ └───────────┘
        ▲    ▲   模型申报 dnd（勿扰，进 dnd 窗口）              │
        │    │                                                  │ 模型申报 closed/dnd
        │    │           窗口到期自动降级 / 她主动发消息           │
        │    └────────────── ┌───────────┐ ◀────────────────────┘
        │                    │   dnd     │
        │                    └───────────┘
        │
        │  回归 attentive 的三条路（全部宿主执行）：
        ├─ ① 出站蕴含：她向该对话发出任何消息（含跨会话主动联系）
        ├─ ② 轰炸唤醒（仅 ring-only）：消息压力阈值 → 宿主调度回放回合
        └─ ③ 自然注意到：自动推进中模型让她拿起手机（phoneCheck 信号）→ 宿主推送回放回合
```

三条铁律：

1. **退出由模型申报**。`attentionAfter` 只在她**实际发送了消息**的回合采信（沉默回合的"勿扰"是心想不是操作）；默认 `open`（仍在看），模型不主动结束就一直在看——保守方向，杜绝"模型懒得写就集体失明"。
2. **出站蕴含注意力**。任何一条她发往该对话的消息立即置 `attentive`——必须看着才能打字。这是状态机最重要的自愈路径，也是模型主导回归的通道。
3. **`ring-only`/`dnd` 只切断"消息→回合"一条边**。自动推进、世界事件、到期意图照旧；她的生活在没有这个对话时继续。

## 3. 看不见时：分流与台账

### 3.1 入站路径

```text
消息到达
  ├─ attentionGate 关闭 → 现行路径（不变）
  └─ 开启
       ├─ 该对话 attentive → 现行路径（TurnEngine 缓冲、debounce、supersession 全保留）
       └─ ring-only / dnd → 仅入未读台账，不 bufferUserNarrative、不调度消息回合
```

- 台账条目：`(conversationKey, entryId, 发送者, 摘要, 到达时间)`；群聊按发送者分记、回放保序。
- `currentParticipant.unreadMessageCount` 从台账实时派生，口径统一。
- 诊断日志（standard 级）：`消息未入回合 注意力=ring-only 对话=%s 未读=%d`——避免"bot 坏了"的误判。
- `inboxReasonLabels`（muted/paused 回放先例）追加 `attention-away`；用户侧暂停/静音与本设计正交，可叠加。

### 3.2 锁屏摘要（away 期间自动推进的常设事实）

ring-only/dnd 期间，每个自动推进回合的载荷携带一行**摘要级**锁屏事实（内容不注入，只有计数与发送者）：

```json
{ "lockscreen": { "unread": [ { "conversation": "qq-private:28…", "sender": "用户", "count": 7, "lastAt": "…" } ] } }
```

提示词一行（元数据风格，对齐 CHANNEL CONTEXT）：*LOCKSCREEN 未读是到达事实的摘要；只有剧本写她拿起手机看了，这些内容才对她成为观测——没看就当它们不存在，不得引用。*

这行摘要就是"自然注意到"的全部土壤：模型写她的生活（通勤、排队、躺床上），写不写"顺手看了眼手机"是它的叙事自由——宿主不催、不表、不定概率。

## 4. 回到可见：三条回归路

### ① 出站蕴含（模型主导，最常见）

她在任何回合（多为自动推进）向该对话发出消息——状态立即 `attentive`，台账中她"此刻已读"的部分自然进入她的决策上下文（出站剧本即依据）；后续消息驱动恢复。

### ② 自然注意到 → 回放回合（两步，宿主执行）

用户愿景的原句落地："等到某一次自动advance里它看手机了，再把未读的消息内容一起推送给它"：

1. 自动推进回合里，模型基于锁屏摘要把她写去拿手机，输出轻量信号 `phoneCheck: [conversationKey…]`（仅 ring-only 态可含该对话；dnd 对话不可出现在此——勿扰是她的明确意志）；
2. 宿主看到 phoneCheck → 该剧本回合照常落账 → **紧接着调度一个回放回合**（复用 muted/paused 收件箱回放的先例与投影），注入完整未读，状态 → `attentive`；
3. 回放回合里她可能回、可能看完不回——后者由她输出新的 `attentionAfter` 决定去留。

两步设计保证**内容零泄漏**：她没拿手机之前，未读的具体内容从未进入任何提示词，只有计数。回放事件与通道标注（M4）同族，宿主-authored 确定性投影：

```json
{ "type": "unread-replay", "conversation": "qq-private:28…",
  "window": { "from": "…", "to": "…" },
  "entries": [ { "at": "…", "sender": "用户", "content": "在吗" }, … ],
  "omitted": { "count": 14, "note": "此前另有 14 条，略" } }
```

- 私聊：全部未读，上限 20；超出取尾部、`omitted` 计数带过头部。
- 群聊：尾部 12 条 + `omitted` 计数；同发送者连续刷屏合并为计数行（"某人连发 8 条"）。

### ③ 轰炸唤醒（宿主算法，仅 ring-only）

```text
每条入站（ring-only 路径）后评估：
  burst  = 最近 10 分钟该对话消息数 ≥ 3
  pileup = 未读总数 ≥ 5（群聊 ≥ 8）
  night  = 故事本地 23:00–07:00 → 暂缓（消息照入账，唤醒推迟到次日活动时间）
  burst || pileup 且非 night
    → 2–10 分钟随机延迟调度回放回合（避免秒回的遥控器感；single-flight 复用 Scheduler 唤醒仲裁）
```

夜间暂缓不是"判定她睡没睡"，只是**不为刷屏叫醒服务**——自然注意到和出站路径在夜间照常成立（模型写她醒了看手机，宿主照推）。dnd 态此路完全关闭：勿扰是她的明确意志，只有时间窗到期、或她自己发消息才能解除。

## 5. 对话结束信号（模型主权的输出合约）

回复回合的 `interaction` 新增可选字段：

- `"open"`（默认）：这轮说完但对话仍开着——仍是 attentive，后续消息照常驱动。
- `"closed"`：她主动收束（道晚安、明确告辞、话题自然结束后离开）→ 状态 → `ring-only`。**轰炸算法照常适用**——这正是"对方还想聊、连发消息把她炸回来看一眼"的价值场景。
- `"dnd"`：她明确不想再被这个对话打扰（生气、烦了、拉黑边缘）→ 状态 → `dnd`：`dndHours`（默认 8h，可设"到次日早晨"）内抑制轰醒，到期自动降级 ring-only；期间她主动发消息立即解除。

归一化：非法值回落 `open`；仅发送回合采信。与用户侧运行相位词汇严格区分：用户的是 静音/暂停（管"她发不发"），她的是 勿扰/仅响铃（管"她看不看"）。

## 6. 与现有系统的精确对接

| 系统 | 关系 |
|---|---|
| TurnEngine | 不改内核。分流发生在 `bufferUserNarrative` 之前；attentive 路径零变化 |
| Scheduler 唤醒仲裁 | 回放回合（phoneCheck 触发 / 轰炸触发）作为新唤醒源进仲裁，exclusive gates 复用；与到期意图唤醒合并时回放随首个回合捎带 |
| 收件箱回放（muted/paused 先例） | 回放回合复用同一投影形态与生命周期管理 |
| 端点注册表 / 通道标注（M1/M4） | 对话键 = 端点感知 conversationKey；回放事件携带通道上下文，与 `[QQ·私]` 标注嵌套 |
| 群意愿门 / agency 窗口 | 不变：回来看 ≠ 想回；回放回合照常过意愿门 |
| 提示词 | 仅三处增量：LOCKSCREEN 摘要行、UNREAD REPLAY 元数据行、`attentionAfter`/`phoneCheck` 输出教学。CHANNELS/unread 原文不动——本设计是给它们的机制兑现 |
| typ·0 桌面 | 后续状态栏可显示各对话注意力态与未读数；本设计不依赖桌面端 |

## 8. 边界情况

- **冷启动/首次联系**：新参与者第一条消息强制 attentive（她注意到新对话）——onboarding 不被状态机卡死。
- **多端点同人**：台账按对话（端点）分记；她用微信回复只清微信侧未读，QQ 侧继续挂账——真实且无害。
- **跨会话主动联系**：目标对话置 attentive，但**不自动回放**旧未读（她主动找人通常有当下动机，不是来清账的）；该对话旧未读等下次入站或她翻看时处理。
- **dnd 期间的 phoneCheck**：勿扰对话不可出现在 phoneCheck 列表（合约层禁止）；模型写了也归一化剔除——她的明确意志优先于叙事方便。
- **故事暂停（paused）**：自动推进也停，回放回合无从调度——台账持续累积，恢复后首个自动推进照常携带锁屏摘要。
- **读而不回的台账清算**：回放回合里她看完没回且 `attentionAfter: closed`——该批未读视为**已读历史**入剧本（她确实看过了），台账清零、状态回 ring-only。v1 以"是否回放回合消费"为清算边界。
- **回放大小**：`omitted` + 尾窗保证回放事件 O(窗口)；入载荷前过 compact 预算。
- **禁用路径**：`enabled:false` 不建台账、不注册唤醒源、提示词三处增量不注入——回归零差异。

## 9. 测试策略

- 转换归一化纯函数：`attentionAfter` 非法值/沉默回合回落 open；dnd 对话从 phoneCheck 剔除；出站蕴含翻转。
- away 分流：mock 入站 → 断言 TurnEngine 无回合、台账入账、`unreadMessageCount` 派生。
- 锁屏摘要投影：计数/发送者/时间，内容零泄漏断言。
- 回放回合：phoneCheck 触发链、私聊超限头摘要、群尾窗、同发送者合并；轰炸唤醒阈值边界、single-flight、夜间暂缓到次日。
- 集成回归护栏：开关往返与现行输出逐字节一致。

## 10. 分期落地

| 期 | 内容 | 独立价值 |
|---|---|---|
| AG-M0 | `attentionAfter` 合约 + away 分流 + 未读台账 + 锁屏摘要 | 消息不再遥控她；退出对话有实感 |
| AG-M1 | phoneCheck + 回放回合（自然注意到路径） | 用户愿景完整闭环：拿手机→看未读→决定回不回 |
| AG-M2 | 轰炸唤醒（burst/pileup/夜间暂缓/single-flight） | 被刷屏时她会回来看一眼 |
| AG-M3（v2 备选） | 亲密度/发送者多样性权重、dnd"到次日早晨"语义、桌面状态可视化 | 调优 |

每期结束全量测试绿 + `enabled:false` 回归护栏常驻。

## 11. 风险与开放问题

- **用户体验风险**：用户视角"bot 不理我"可能被当成故障。缓解：文档明示特性 + 诊断日志 + Console 可见状态 + 一键关闭。
- **模型申报保守性**：弱模型可能从不输出 closed（回退为现行行为，无害）或过度输出（频繁失明）。上线后统计申报分布再调教学措辞；默认 open 的兜底方向保证不会集体失明。
- **phoneCheck 语义漂移**：模型可能在剧本没写拿手机时输出 phoneCheck（字段与剧本脱节）。归一化层可校验：剧本含设备/看手机相关锚词才采信（宽松白名单），实测后决定收紧程度。
- **开放问题**：读而不回的清算粒度（按整批 vs 按条）；群聊"余光"是否需要第四弱态（人在群里没看私聊）——v1 不做，记录在案。
